# Skillify：把会话流程沉淀为技能

你的任务是把本会话中刚完成的一个可复用流程捕获为**纯 Markdown 技能**
（零 Python 代码——技能是数据不是代码，这是 agent 自学习的关键）。

## 输入材料

回顾本会话：
- 做了什么可复用的流程？输入/参数是什么？
- 有哪几个步骤（按序）？每步的成功标志是什么
  （不是"写了代码"而是"PR 合并且 CI 绿"这类可验证产出）？
- **用户在哪里纠正/引导了你**？（这些纠正往往是技能最有价值的部分——
  它们是用户的硬偏好和硬约束）
- 用了哪些工具/权限？是否用了子代理？

## 步骤

### 1. 分析会话

先自己梳理出：流程名（建议）、一句话描述、编号步骤列表、每步的
产出与验证标准、用户纠正点。**先分析完再问**，不要一上来就问。

### 2. 用 ask_user 访谈（2-3 轮，简单流程可 1 轮）

所有问题一律走 `ask_user` 工具（不要纯文本提问）：

**第 1 轮（高层确认）**：给出建议的技能名 + 描述 + 目标，让用户确认或改名。
**第 2 轮（步骤细化）**：展示编号步骤列表；问关键点——
- 哪些步骤需要用户中途确认（合并/发消息/删除类不可逆动作必须问）？
- 哪些步骤相互独立可并行？
- 触发方式：什么时候该用这个技能？给 2-3 个触发短语示例。
**第 3 轮（收尾）**：还有什么坑/注意事项要写进技能？

**访谈原则**：信息够了就停，简单流程不要过度提问；
用户每轮都有自由输入选项，不要替用户设"需要微调"这类选项。

### 3. 写 SKILL.md 并保存

用 `skill_manage` 工具（action=create）保存。格式：

```markdown
---
name: <技能名（小写连字符）>
description: <一句话描述——什么时候用这个技能>
---

# <技能标题>

## 适用场景
- <触发时机与示例短语，如"x 发布前检查"、"release checklist">

## 步骤

### 1. <步骤名>
<做什么、产出什么、怎么验证成功>

### 2. <步骤名>
...

## 规则（硬约束）
- <用户纠正沉淀的硬规则，如"永远不要直接 push main 分支">
- <必须/禁止的事项>

## 注意事项
- <坑与边界情况>
```

写法要点：
- 步骤要写成"下次执行时照着做就能复现"的粒度（含工具名与关键参数）
- 可并行的步骤用子编号（3a、3b）；需要用户操作的步骤标题加 `[用户]`
- description 决定技能被检索/触发的概率，写"什么时候用"而不是"是什么"

### 4. 确认

保存后告诉用户：技能路径、如何触发（`/技能名` 或自动触发）、
如何后续改进（`skill_manage action=patch`）。

## 铁律

- **纯 Markdown**：不生成任何 Python 代码；需要执行命令就写在步骤里
- **用户纠正优先**：会话中用户纠正过的地方必须沉淀进"规则"段
- **不要覆盖已有技能**：同名时先 `skill_manage action=list` 查，
  征求用户是更新还是改名
